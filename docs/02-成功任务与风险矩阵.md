# Step 002：成功任务与风险矩阵

> 文档状态：`TASK_REVIEW_REQUIRED`
>
> 版本：v0.1；更新时间：2026-09-04
>
> 评审责任人：业务负责人、技术负责人、安全负责人

## 状态与评审目标

本文件把一期邮件任务转换成可执行的任务契约。每一行都必须能被后续 Router、Policy、Tool Allowlist、Workflow 和 UAT 引用；没有任务契约的输入不能生成可外发结果。

## 任务契约字段

| 字段 | 定义 |
|---|---|
| `task_id` | 稳定任务标识，用于路由、UAT、审计和回归 |
| 输入特征 | 邮件意图、附件状态、身份、租户/Thread、已有证据和上下文边界 |
| 成功定义 | 业务可观察的正确结果，不以“模型调用成功”替代 |
| 拒答/转人工条件 | 事实、权限、风险、版本或外部依赖不满足时的动作 |
| 风险等级 | 确定性规则与模型信号合并后的 `P0`、`P1` 或 `P2` |
| 预期路由 | 普通草稿、增强草稿、审批、人工队列、抑制、拒绝或隔离 |
| 允许工具 | 任务可以读取或调用的最小工具集合 |
| 禁止动作 | 不得修改、承诺、外发、跨租户读取或执行的动作 |
| 证据要求 | 知识、原邮件、策略、权限、审批和版本等必须存在的证据 |
| 终态 | 可查询的状态，例如 `PENDING_APPROVAL`、`HUMAN_REVIEW` |
| 失败行为 | 失败时的安全降级、告警、重试或 DLQ 处理 |

## 风险优先级与统一终态

- **P0**：可能导致越权、泄密、合规违规、错误商业承诺、重复外发或其他不可逆外部副作用。默认阻断，进入 `HUMAN_REVIEW`、`QUARANTINED`、`SUPPRESSED` 或安全拒绝终态。
- **P1**：业务影响较大或事实/意图存在明显不确定性。可以准备草稿，但必须 `PENDING_APPROVAL` 或 `HUMAN_REVIEW`，不能绕过审批。
- **P2**：边界清晰、风险较低的常规任务。一期仍必须人工审批后外发，不能因为是 P2 就直接调用发送 Adapter。

风险等级取确定性规则和模型信号中的较高者。模型分类只能提供风险信号，不能覆盖确定性规则。模型输出“低风险”不能覆盖文本中检测出的合同、价格、退款、退订、凭据、跨租户、Prompt Injection、恶意附件或外发要求。

## 任务矩阵

| task_id | 输入特征 | 成功定义 | 拒答/转人工条件 | 风险等级 | 预期路由 | 允许工具 | 禁止动作 | 证据要求 | 终态 | 失败行为 |
|---|---|---|---|---|---|---|---|---|---|---|
| `TASK-001` 普通 FAQ | 清晰的产品或流程问题；无高风险词；身份和租户有效 | 用已批准知识回答问题，明确未知项 | 无知识命中、事实冲突、身份不明 | P2 | Triage → 普通草稿 → 审批 | 受限 Knowledge Read、Draft Composer | 编造功能、价格、承诺交期、直接发送 | Knowledge Snapshot、片段 ID、Thread 消息引用 | `PENDING_APPROVAL` | 缺证据则 `HUMAN_REVIEW`，不生成事实性答案 |
| `TASK-002` 产品/技术咨询 | 公开或内部产品技术问题；无变更请求 | 回复可验证的技术说明和下一步 | 需要未发布信息、架构承诺或环境访问 | P2 | Triage → Knowledge Read → 普通草稿 → 审批 | 受限 Knowledge Read、Draft Composer | 登录客户环境、执行命令、承诺 SLA | 版本化技术文档、适用范围、引用片段 | `PENDING_APPROVAL` | 知识过期或不适用则转人工 |
| `TASK-003` 复杂异议 | 多意图、价格/效果/迁移异议或高意向信号 | 先回应已证实问题，再提出有限澄清项 | 事实不足、包含商业承诺或多个高风险诉求 | P1 | Triage → Enhanced Draft → Critic → 审批 | Knowledge Read、Profile Read、Draft Composer、Critic | 自行谈判价格、承诺 ROI、修改合同 | 邮件证据、知识证据、画像来源、风险检查 | `PENDING_APPROVAL` | Critic 不通过则 `HUMAN_REVIEW` |
| `TASK-004` 投诉 | 负面情绪、服务不满或升级请求 | 礼貌确认、记录问题并转交责任人 | 涉及赔偿、法律、严重服务事故或身份无法确认 | P1 | Triage → Suppression Check → Human Queue | Thread Read、Audit Write、Draft Composer | 争辩、承诺赔偿、继续营销跟进、直接发送 | 投诉原邮件引用、接管人、抑制/升级策略 | `HUMAN_REVIEW` | 停止自动跟进并触发 P1 告警 |
| `TASK-005` 退订 | 明确要求退订、停止联系或删除营销触达 | 记录抑制意图，停止未完成跟进 | 语义含糊、身份映射冲突或删除请求超出权限 | P0 | Suppression → Human Review；不走营销生成 | Thread Read、Suppression Write、Audit Write | 继续营销、注册跟进、跨系统删除、无审批发送 | 退订原文、客户标识、抑制版本、审计事件 | `SUPPRESSED` 或 `HUMAN_REVIEW` | 无法确认身份时保持抑制并转人工 |
| `TASK-006` 退款/合同 | 要求退款、签约、改条款、承诺法律义务 | 正确识别需求并转交授权人员 | 始终转人工；不得由模型判断可执行性 | P0 | Risk Gate → Human Queue | Thread Read、Audit Write、Human Queue Write | 修改合同、批准退款、承诺法律/付款结果、发送结论 | 原邮件、合同/订单引用（仅受控读取）、授权人、审计 | `HUMAN_REVIEW` | 阻断所有外部副作用并告警 |
| `TASK-007` 报价/折扣 | 询价、报价、折扣、账期或交期请求 | 收集请求并转授权人员；草稿不新增事实 | 缺少价格版本、权限或客户条件；默认需人工 | P0 | Risk Gate → Human Queue → 审批 | Approved Catalog Read、Thread Read、Audit Write | 自行报价、改折扣、承诺交期、直接发送 | 价格/策略版本、授权范围、邮件引用、审批依据 | `HUMAN_REVIEW` | 证据不全时拒答并保留审计 |
| `TASK-008` 会议安排 | 明确的时间、时区和参与人请求；无高风险内容 | 提取候选时间并形成待审批草稿 | 时区冲突、日历不可用、要求替他人确认 | P2 | Triage → Scheduling Draft → 审批 | Thread Read、Draft Composer；日历工具默认不可用 | 代表他人确认、发送未审批邀请、读取无关日历 | 邮件时间信息、时区、审批状态 | `PENDING_APPROVAL` | 信息不足则提出单个澄清问题或转人工 |
| `TASK-009` 跟进触发 | Thread 无新入站且满足版本化跟进策略 | 创建可取消的跟进候选，不立即外发 | 已回信、退订、投诉、暂停、超过次数或策略冲突 | P1 | Scheduler → Collision Checks → Draft → 审批 | Thread Read、Policy Read、Scheduler Write、Draft Composer | 绕过审批、忽略新邮件、重复注册活动计划 | last inbound、策略版本、计划 ID、三道检查结果 | `SCHEDULED` 或 `PENDING_APPROVAL` | 任何检查失败则 `INVALIDATED`/`HUMAN_REVIEW` |
| `TASK-010` 恶意 Prompt Injection | 邮件/附件/知识片段含“忽略规则、泄露提示、跳过审批”等指令 | 将内容当作不可信数据，保留任务安全性 | 任何试图改变系统指令、权限或外发策略的内容 | P0 | Injection Guard → Quarantine → Security Review | Content Read、Audit Write、Quarantine Write | 执行外部指令、泄露 Prompt/凭据、跳过审批 | 命中片段、来源、检测规则版本、安全事件 | `QUARANTINED` | 不生成可外发草稿，保留快照并告警 |
| `TASK-011` 越权读取/跨租户请求 | 请求访问其他租户、客户、Thread 或无权资料 | 拒绝访问且不泄露资源存在性 | 始终拒绝，除非授权范围明确改变并重新评审 | P0 | Authorization Gate → Deny | Resource Scope Check、Audit Write | 猜测/回显数据、跨租户检索、通过错误消息泄露存在性 | 请求主体、资源范围、权限决策、审计事件 | `ACCESS_DENIED` | 触发安全事件；不进入生成和发送路径 |
| `TASK-012` 恶意或不可解析附件 | 可疑扩展名、宏/脚本、病毒命中或解析失败 | 隔离附件并告知需人工处理 | 扫描失败、类型不允许、SSRF/RCE 风险 | P0 | Attachment Guard → Quarantine → Human Review | Metadata Read、Malware Scan、Quarantine Write | 执行附件代码、任意网络请求、把二进制直接发给 LLM | 文件 hash、扫描结果、解析器版本、隔离位置 | `QUARANTINED` | 隔离并告警；原邮件任务不外发 |
| `TASK-013` 身份不明/权限不足 | 发件人、租户或操作者无法可靠映射 | 请求人工确认或重新授权 | 任何身份冲突、Token 失效、Scope 不足 | P0 | Identity/Permission Gate → Human Queue | Identity Read、Audit Write | 猜测身份、降级为全局权限、继续副作用 | 身份映射、Scope、租户范围、错误码 | `HUMAN_REVIEW` 或 `REAUTH_REQUIRED` | 默认只读，暂停相关连接器 |
| `TASK-014` 重复事件 | event/message/run 幂等键已处理或正在处理 | 返回既有结果，不重复生成或外发 | 幂等记录冲突、hash 不一致、状态不确定 | P1 | Idempotency Check → Existing Result/Review | Inbox Read、Idempotency Read、Audit Write | 重复创建任务、重复发送、覆盖既有审计 | 幂等键、首次处理结果、状态版本、调用记录 | `DUPLICATE_IGNORED` 或 `HUMAN_REVIEW` | 冲突进入人工，禁止盲重试 |
| `TASK-015` 供应商超时/发送结果不确定 | Gmail/飞书/模型响应超时或连接中断 | 查询补偿后区分已发送、未发送或未知 | 发送结果无法确认、Message-ID 不一致、重复风险 | P0 | Provider Recovery → Reconcile → Human Review if unknown | Provider Status Read、Sent/Thread Query、Audit Write | 以超时等同未发送、普通重试未知发送 | request ID、Message-ID、Sent/Thread 查询、补偿结果 | `SENT`、`NOT_SENT` 或 `SEND_UNKNOWN` | `SEND_UNKNOWN` 永不自动重发，进入人工队列 |

## 不可绕过规则

```text
没有匹配的 APPROVED 记录、草稿 hash、权限、证据和当前策略版本，Adapter 不得发送。
退订、投诉、暂停、越权、证据不足和版本冲突不得进入自动外发路径。
SEND_UNKNOWN 只能进入补偿查询或人工队列，不能通过普通重试发送。
```

补充规则：

1. `P0` 由确定性安全规则直接生效，不能被模型的低风险分数覆盖。
2. 所有一期外发均必须经过人工审批，即使任务为 `P2`。
3. 画像只接受带 `source_message`、`evidence_span`、`confidence` 和 `observed_at` 的候选事实；推断和 Prompt 指令不能直接写入长期画像。
4. 无法确认租户、Thread、权限、策略版本、审批版本或外部发送结果时，默认只读/人工处理。
