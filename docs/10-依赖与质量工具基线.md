# Step 009：依赖与质量工具基线

> 文档状态：`DEPENDENCY_REVIEW_REQUIRED`
>
> 版本：v0.1；更新时间：2026-09-07

## 依赖分组

生产依赖位于 `pyproject.toml` 的 `[project].dependencies`，包括 FastAPI、Pydantic、SQLAlchemy、Alembic、LangGraph、DeepAgents、OpenTelemetry、psycopg、redis 和 boto3。pytest、pytest-cov、Ruff、mypy、pip-audit 和 CycloneDX 只位于 `dev` 依赖组，不进入运行时镜像。

当前只锁定后续骨架所需的通用框架和基础设施客户端；Gmail/飞书 SDK 由后续连接器步骤按实际契约加入，不提前引入。所有版本使用有界约束，解析后的完整依赖图以 `uv.lock` 为准。

开发机初始化：

```powershell
uv lock
uv sync --dev
```

CI 和干净环境必须执行 `uv sync --locked --dev`；如果 `uv.lock` 与 `pyproject.toml` 不一致，任务失败。禁止用无约束的 `pip install` 作为可复现性证明。`uv.lock` 变化后必须重新生成 SBOM 并审查依赖差异。

## 质量门禁

```powershell
uv lock --check
uv sync --locked --dev
uv run ruff check src tests scripts
uv run mypy src
uv run pytest -q
uv run pip-audit
```

Ruff 使用 Python 3.12、100 列和 `E/F/I/UP/B` 规则；mypy 检查 Python 3.12 且禁止无类型定义；pytest 从 `tests/` 收集测试。任一命令失败都阻断质量 Gate；pip-audit 的漏洞/未解决 advisory 必须记录和评审，不得静默忽略。

## SBOM

```powershell
pwsh -NoProfile -File scripts/generate_sbom.ps1
```

输出为 `sbom/cyclonedx-python.json`，格式为 CycloneDX JSON，生成基于锁定的 uv 虚拟环境并包含项目组件与传递依赖。POSIX 环境使用 `./scripts/generate_sbom.sh`。提交 SBOM 时同时记录生成日期、uv/CycloneDX 版本、组件数量和 SHA-256；SBOM 生成失败或为空时阻断发布。

## Compose 镜像边界

`compose.yaml` 固定 PostgreSQL 16.4、Redis 7.4.1 和 MinIO RELEASE 对应的 OCI digest，禁止 `latest` 和可变标签。`compose.dev.yaml` 仍可覆盖为 SQLite + Mock 离线模式；生产 Gate 必须验证这些 digest 对应的镜像可拉取和健康检查通过。digest 变更必须重新获取、审查并记录来源。

## 安全和范围

依赖、SBOM、日志和报告不得包含真实 Token、Cookie、API Key、OAuth 凭据或客户数据。Step 009 不实现供应商连接器、业务 Graph 或生产部署；质量工具只验证依赖、代码骨架和供应链材料。
