# Step 007：固定开发环境

> 文档状态：`ENVIRONMENT_BASELINE_REVIEW_REQUIRED`
>
> 版本：v0.1；更新时间：2026-09-07
>
> 目标：在干净机器约 10 分钟内完成本地初始化，并在 Docker 不可用时保持 SQLite + Mock 离线演示能力。

当前仓库尚无业务运行时代码和第三方依赖；`pyproject.toml` 只固定项目 Python 范围。Gmail、飞书、LLM 和数据库生产连接器不属于 Step 007。

## 初始化

在仓库根目录执行：

```text
uv python install 3.12
uv sync
pwsh -NoProfile -File scripts/healthcheck.ps1
docker compose -f compose.yaml -f compose.dev.yaml config
```

Windows 主机可使用 `Join-Path (Resolve-Path '.') 'scripts/healthcheck.ps1'` 定位脚本；Linux/macOS 使用 `./scripts/healthcheck.sh`。健康检查不会自动安装软件或写入真实凭据。

## 路径规则

- Windows 配置使用仓库相对路径或环境变量，不写死 `E:\...` 等盘符。
- Linux/macOS 配置使用 POSIX 路径；不要把 Windows 反斜杠写入 Compose。
- 容器内部统一使用 `/app/...`，例如 `/app/scripts/healthcheck-fixture.json` 和 `/app/.runtime/app.sqlite3`。
- 主机密钥、Token 和 OAuth 凭据放在未追踪的 `.env`、Docker secrets 或 KMS 兼容存储，不进入 Compose、Prompt、日志或 Git。

## 离线与严格模式

默认健康检查要求 Python 3.12.x、uv 和有效 fixture；Node.js、Docker/Compose 不可用时会警告但继续输出 `HEALTHCHECK_PASS mode=offline database=sqlite adapter=mock`。这只证明本地 SQLite + Mock 模式可用，不代表生产容器 Gate 通过。

需要验证容器环境时执行：

```powershell
pwsh -NoProfile -File scripts/healthcheck.ps1 -RequireDocker
docker compose -f compose.yaml -f compose.dev.yaml config
```

严格模式下 Docker Engine 24+ 和 Compose v2 缺一不可；不可用时命令失败并报告原因，不自动降级为生产通过。

## 故障处理

| 症状 | 处理 |
|---|---|
| Python 不是 3.12.x | 安装 Python 3.12，再重试；不降低项目声明版本 |
| 找不到 uv | 按 uv 官方安装方式安装，再执行 `uv sync` |
| Node.js 缺失 | 离线模式可继续；需要前端/生产 Gate 时安装 Node.js 20 LTS |
| Docker 缺失 | 使用 SQLite + Mock；生产验证前安装 Docker Engine 24+ 与 Compose v2 |
| Compose 挂载失败 | 使用仓库相对路径，确认容器内路径为 `/app/...`，不要写死盘符 |
| `.env` 配置异常 | 复制 `.env.example` 到未追踪 `.env`，检查变量名；不要粘贴真实密钥到文档 |
| fixture 解析失败 | 恢复 `scripts/healthcheck-fixture.json` 的脱敏 JSON 结构后重跑检查 |
